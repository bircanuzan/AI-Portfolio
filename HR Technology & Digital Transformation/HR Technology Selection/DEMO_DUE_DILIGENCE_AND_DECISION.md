# Structured demo and due-diligence protocol

## Demo scenarios (same script for every vendor)
1. Employee creates a fictional HR document request via accessible mobile intake.
2. HR agent routes the case to a qualified team; HR-only notes remain hidden from employee.
3. Manager attempts unauthorised access to a grievance record — denial is recorded.
4. Case breaches fictional SLA and triggers a named-human escalation.
5. HR changes catalogue wording, tests in sandbox and publishes through approved change.
6. HR administrator exports a de-identified service summary and verifies reconciliation.
7. An integration fails; vendor shows a retriable exception without duplicate tickets.

## Procurement score dimensions
| Criterion | Weight | What constitutes '5' |
|---|---:|---|
| Functional fit | 30% | All critical journeys shown end-to-end with evidence |
| Security and privacy | 25% | Independent documented controls and mandatory gates pass |
| Integration fit | 20% | Validated HRIS handoff and no uncontrolled financial writes |
| Employee experience | 15% | Accessible employee journeys backed by usability evidence |
| Three-year total cost | 10% | Transparent fixed/variable/support cost under scenario |

## TCO comparison structure
Model subscription tiers, implementation, interfaces, testing, migration, training, support FTEs, maintenance, vendor exit and renewal escalators. All assumptions must be approved, and costs must be normalized to one currency and one service population.

## Recommendation gates
1. Functional/security proof; 2. scoring moderation; 3. proof-of-concept risk review; 4. procurement/legal approval; 5. actual contract decision. Weighted scoring must not override a failed mandatory gate.

## Decision memo outline
Context -> options -> evaluation evidence -> mandatory checks -> sensitivity analysis -> TCO -> key risks -> recommended next decision -> dissenting opinions -> signoff. The accompanying example data is invented and **must not** be presented as an actual vendor evaluation.
